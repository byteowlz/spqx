# Spqx Voice Lab

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack
Plain HTML/CSS/JavaScript and Bun server, explicitly confirmed through user selection. Code-first workflow confirmed separately.

## Users
The owner auditioning fictional German voices across desktop and phone browsers.

## Product Purpose
Genuinely dial a voice using PCA, listen and A/B, then explicitly save the liked result. Not prompt sliders disguised as latent controls.

## Operating Context
Small standalone service registered in Owlznest, which is a directory rather than an app host. First version explicitly uses the already-tested experimental Qwen SDK path while native spqx MLX/GGML integration remains separate.

## Capabilities and Constraints
Use the existing model-scoped1024D0.6BBase space; three source voices support only a toy two-axis PCA. Explicit bounded previews with current compute admission, no inference per slider movement, no cloud fallback. Save self-contained drafts, not implicit canonical registry promotion or recognition enrollment. Keep raw reference/text and model/basis recipe. User explicitly requested no operator key for this trusted-tailnet lab; reaching its private listener grants access to previews/drafts/media. Preserve same-Origin/Host checks and resource limits; do not widen network exposure or apply this policy to other apps. Runtime data and audio stay outside git. No neural-weight training per edit.

## Product Principles
- Show which settings produced the audio, not just the current sliders.
- Save the exact auditioned audio, not a fresh regeneration.
- Separate draft persistence, registry promotion and enrollment.
- Distinguish working SDK evidence from unverified native parity.
