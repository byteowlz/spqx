# Spqx Voice Lab

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack
Plain HTML/CSS/JavaScript and Bun server, explicitly confirmed through user selection. Code-first workflow confirmed separately.

## Users
The owner auditioning fictional German voices across desktop and phone browsers.

## Product Purpose
Genuinely dial a voice using PCA, listen and A/B, then explicitly save the liked result. Not prompt sliders disguised as latent controls.

## Operating Context
Small standalone service registered in Owlznest, which is a directory rather than an app host. The first version used the explicitly experimental Qwen SDK path. r3 adds an explicitly selected native spqx GGML provider; it reuses the existing whole-pipeline engine in bounded per-preview processes, not another SDK service. MLX and persistent warm editing remain separate qualification work.

## Capabilities and Constraints
Use the existing model-scoped1024D0.6BBase space; three source voices support only a toy two-axis PCA. Explicit bounded previews with current compute admission, no inference per slider movement, no cloud fallback. Capture the complete effective vector, exact audition WAV/text, scope and fitted bank/recipe. SDK mode saves self-contained drafts. Native mode can offer explicit synthesis-only canonical Save through voqx; never promote on Preview or enroll recognition/train weights. Keep raw audio for listening and explicitly approved migrations, while compatible runtime reuse consumes the frozen vector. User explicitly requested no operator key for this trusted-tailnet lab; reaching its private listener grants access to previews/drafts/media and, when enabled by the native provider, explicit synthesis-only canonical Save. This is not recognition enrollment or session/tool authority. Preserve same-Origin/Host checks and resource limits; do not widen network exposure or apply this policy to other apps. Runtime data and audio stay outside git. No neural-weight training per edit.

## Manual calibration
An optional private 100-candidate vector-only bank supports six blind human trait ratings, two discrete judgements (voice presentation and age band, each with Unclear) and separate naturalness, exclusions and notes. Requested descriptions remain hidden and are not labels; midpoint scores are not persisted until explicit Save. Exact-audio revisions and durable retry ids protect annotations. This route never infers traits, generates audio, trains weights or promotes identities. Broader PCA/supervised control learning needs real ratings and held-out listening first; retro-console styling remains later. Inherit the established Chalk workbench without claiming a selected production design.

## Product Principles
- Show which settings produced the audio, not just the current sliders.
- Save the exact auditioned audio, not a fresh regeneration.
- Separate draft persistence, registry promotion and enrollment.
- Distinguish working SDK evidence from unverified native parity.
